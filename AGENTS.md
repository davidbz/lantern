# AGENTS.md

Guidance for AI coding agents working in this repository (`CLAUDE.md` and `GEMINI.md` are symlinks to this file).
Humans: see [README.md](README.md).

## Conventions (read before writing Go)

- [Architecture](.github/instructions/golang/architecture.md): data-oriented design, DI with `go.uber.org/dig`,
  config only in `internal/config`, logger from context (`log/slog`), no panics outside `main.go`.
- [Coding style](.github/instructions/golang/coding-style.md): early returns, no `else`, no named returns,
  wrap errors with `%w`, `ctx` first.
- [Testing](.github/instructions/golang/testing.md): black-box `_test` packages, testify `require`,
  mockery mocks, table-driven subtests, 90%+ coverage.

Most of these rules are enforced by `.golangci.yml`; do not weaken the lint config or add `//nolint` without a
specific linter name and an explanation.

## Layout

- `cmd/<name>/main.go`: one directory per binary (default `cmd/app`); composition root only.
- `internal/`: all application code. No `pkg/`.
- `internal/mocks/`: generated by mockery; never edit by hand.

## Commands

| Task | Command |
| --- | --- |
| Format | `make fmt` |
| Lint | `make lint` (`make lint-fix` to auto-fix) |
| Test | `make test` (regenerates mocks, `-race -shuffle=on`) |
| Regenerate mocks | `make mocks` after changing an interface or `.mockery.yaml` |
| Vulnerabilities | `make vuln` |
| Everything CI runs | `make ci` |

Project tools (mockery, govulncheck, go-licenses) are `tool` directives in `go.mod`: run them with `go tool <name>`
and never `go install` them. Add a dependency with `go get`, then `make tidy`.

## Before finishing

Run `make fmt lint test` and make sure all three pass. Commit regenerated mocks together with interface changes.
